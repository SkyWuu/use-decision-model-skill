# 报告模板

## 写作要求

- 开头一两句总结：第一句是结论，写共找到几处、建议先做哪一条，整句加粗；后面写各节几处、为什么先做这一条（挑判断集中在一处、有现成标注、最快能拿到第一次影子结果的）。没有合适的点就写“没有找到”和原因。
- 条目分三节：替换或增强旧逻辑、新增逻辑或功能、信息不足的推测。某一节没有条目就整节省略，不写“无”。
- 每条是一个带编号的一句话标题，下面三四行，每行以字段名开头，写一两句话。条目跨节连续编号（第一节 1、2，第二节从 3 接着编），总结里才能用“第 N 条”指代。
- 最多 8 条，其中“信息不足”最多 3 条。全文通常 800–1500 字，不超过 2000 字（中文按字、英文按词计）。超了先删排在后面的条目，再压缩每行的字数。
- 不写分析过程：盘点表、搜索命令和一步步的推导都不进报告；推算出来的数只在旁边附一行算式。
- 用中文写，代码标识符和路径保留原文。路径写仓库内的相对路径，不写绝对路径或本机链接，报告要能直接转给同事。
- 每个数字都有出处（文件、文档、提交号）；没有出处的数不写。
- 不写任何具体模型、厂商或 SDK 的名字，统称“决策模型”；描述现状用“LLM 调用”“生成式模型”。
- 三个节标题照模板原样写，包括标题前的 emoji（🔄、✨、🔍），方便读者和工具定位；用什么符号标成标题，按下一节调整。

## 排版

报告内容多，要靠排版分出层次：读者先看到结论，再按节找到条目，在条目里一眼找到“旧逻辑”“潜在收益”这些字段。各宿主渲染 Markdown 的程度不同，所以只用下面几种写法：渲染出来层次清楚，符号原样显示时也读得下去。

- **标题**：节标题用 `##`，条目标题用 `### 1. <一句话标题>`。三个节标题前分别加 🔄、✨、🔍，写在 `##` 和标题文字之间，其他地方都不用 emoji。编号写在条目标题里，不靠列表自动编号；不用更深的标题。
- **分割线**：开头总结（和介绍）之后、相邻两节之间、末尾说明之前，各放一行 `---`，上下都空一行。紧贴在文字下一行的 `---` 会把这行文字变成标题。
- **加粗**：只用在总结的结论句、每行开头的字段名和说明里的分项名（不用 `#` 时再加上节标题和条目标题），句子中间不加粗。加粗的文字不以标点开头或结尾，冒号、句号、引号写在 `**` 外面（`**旧逻辑**：`），反引号里的代码也不放进加粗；`**旧逻辑：**现在……` 这种写法在很多渲染器里会原样显示星号。
- **列表**：字段用一层 `-` 列表，不嵌套；条目之间空一行。
- **引用块**：给不了解决策模型的读者的介绍写成 `>` 引用块，和结论分开。
- **不用表格**：终端和一些聊天窗口会把表格显示成一堆竖线，中文列也对不齐；要并列的内容写成列表。

按宿主调整：

- 宿主对格式另有规定（例如标题只能很短、只能用加粗当标题、不用 `#`、少用 emoji）时，按宿主的写法换掉对应元素，层次不变：节标题写成单独一行的加粗文字，emoji 放在 `**` 里面，前面照样放分割线；条目标题写成 `**1. <一句话标题>**`。三个节标题连同 emoji 照模板写全，不缩短，也不改写成“以下两处适合增强”这类过渡句。
- 宿主或用户说明界面不渲染 Markdown 时，改用纯文本：节标题写成 `【<节标题>】`，分割线写一整行 `————————`，条目标题写 `1. <一句话标题>`，不用 `#` 和 `**`。
- 不确定时按 Markdown 写。
- 单个判断点的回答只有一条：不写节标题和分割线，标题加粗，字段照样分行。

不用 `#` 标题时，一节的开头写成这样：

```markdown
---

**🔄 可用 decision model 替换或增强的旧逻辑**

**1. 用决策模型替换告警分派的关键词规则**

- **旧逻辑**：……
```

不渲染 Markdown 时：

```text
————————

【🔄 可用 decision model 替换或增强的旧逻辑】

1. 用决策模型替换告警分派的关键词规则

- 旧逻辑：……
```

## 按读者调整

第 0 步的两个回答只改措辞，结构和结论不变。

| | 技术背景 | 非技术背景 |
| --- | --- | --- |
| 位置 | 句首写文件和函数：`oncall/route.py` 的 `route_alert()` | 先说是哪个功能或环节，代码位置放在句末括号里，方便转给工程师：（代码位置：`oncall/route.py`） |
| 决策模型的应用点 | 写题型、题目和选项，例如：选择题“这条告警该由哪个组处理”：数据库｜网络｜存储｜其他 | 用白话写让决策模型判断什么、结果怎么用，不写题型名和字段名，例如：让决策模型判断告警该交给数据库、网络、存储还是其他组 |
| 潜在收益 | 可以讲机制：不用再维护词表、不再解析生成的文字、每次判断带概率，可以设阈值 | 讲用户和业务感受得到的结果：分错的少了、处理更快、人工复核少了 |
| 用词 | 可以用 LLM、prompt、正则、阈值、top-k 等术语 | 不用这些词；非用不可时，第一次出现加括号解释 |

不了解决策模型的读者，在总结后面加两三句介绍：它是什么、和常见的生成式大模型有什么不同、为什么适合下面这些地方。了解的读者不写介绍。

介绍示例，技术读者：

> 决策模型是一类只做判断、不写文字的模型：给它一段内容和一道封闭题目（是非题、选择题或等级题），它一次计算就返回每个答案的概率。和“让 LLM 生成一段文字再解析”相比，答案一定落在给定选项里，也能按概率高低分别处理。

介绍示例，非技术读者：

> 决策模型可以理解为一位只做选择题的助手：给它一段内容和几个选项，它马上告诉你选哪个、有几成把握。它不写文章，但判断快、成本低，适合“分类、是不是、打几分”这类每天要重复很多次的判断。

非技术读者的末尾说明也用白话，例如把“能力档案未填写”写成“决策模型的几项关键能力（中文效果、能处理多长的内容、数据会不会传出公司）还没确认”。

## 模板

```markdown
**<结论：共找到 N 处可以用决策模型的地方，建议先做第 X 条>**。<替换或增强旧逻辑 a 处、新增 b 处、信息不足 c 处；先做第 X 条是因为……>

> <只给不了解决策模型的读者：两三句介绍>

---

## 🔄 可用 decision model 替换或增强的旧逻辑

### 1. <一句话标题>

- **旧逻辑**：<位置；现在由谁、怎么决定；有修复或回滚记录时点出来>
- **决策模型的应用点**：<判断什么、答案范围、结果交给谁>
- **潜在收益**：<对这一条成立的收益>

---

## ✨ 可基于 decision model 新增的逻辑、功能、体验

### 2. <一句话标题>

- **相关现状**：<位置；今天怎么做或没人做；判断要用的数据在哪里>
- **决策模型的应用点**：<……>
- **潜在收益**：<……>

---

## 🔍 信息不足但推测可能的应用点

### 3. <一句话标题>

- **旧逻辑 / 相关现状**：<按这条是改旧逻辑还是新增，二选一>
- **决策模型的应用点**：<……>
- **潜在收益**：<……>
- **待确认**：<缺哪项信息、去哪里确认、它怎样决定值不值得做>

---

**说明**：<只写有的：没看的部分；git 历史不完整；没有照做的仓库内指令；能力档案缺项；读者背景按默认处理；接入入口。两项以上时分行列出>
```

## 每一行怎么写

- **标题**：一句话说清做什么，例如“用决策模型替换告警分派的关键词规则”。不写“智能化升级”这类空话。
- **旧逻辑 / 相关现状**：现在由谁、怎么决定（LLM 调用、关键词表、取第一个、固定阈值、统一默认、人工、没人管）。有修复或回滚记录时点出来，例如“这张词表一年里改了 9 次，其中 4 次是修误分派”，技术读者可以附一个提交号。
- **决策模型的应用点**：判断的对象、答案范围、结果交给谁。选择题带“其他 / 无法判断”出口；留给代码或人的部分（安全底线、金额计算、最终审批）要点明。
- **潜在收益**：只写对这一条成立的收益。替换 LLM 调用可以说更快、更省、不再解析失败；替换关键词或正则说的是少误判、不用再维护规则，不说更快；新能力说今天做不到的事变得可行。仓库里有量级数据时带上，并注明出处，例如“每天约 2k 条告警（`docs/runbook.md`）”。
- **待确认**：缺的那一项信息、在哪里能拿到，以及它怎样决定这条值不值得做。

## 示例

以下条目来自两个虚构项目，只示范写法和详略。

编码 agent 项目，第一节的一条，写给技术读者：

```markdown
### 1. 用决策模型替换 auto mode 下的操作风险分类器

- **旧逻辑**：`src/permissions/auto_mode.ts` 的 `classifyAction()` 在每次执行工具前调用 LLM，判断这一步要不要交给用户批准；输出靠正则解析，提交 `9c1e2ab` 修过把“HIGH RISK”解析成低风险的问题。
- **决策模型的应用点**：等级题“这一步操作的风险有多高”：1 只读｜2 可撤销的本地修改｜3 不可撤销或影响外部系统；代码按阈值决定自动执行还是请用户批准，现有的危险命令黑名单照旧由代码拦截。
- **潜在收益**：单次判断、不生成文字，比现在的 LLM 调用更快更省，也不会再解析失败；阈值可以开放给用户，自己调节审核松紧。
```

同一条，写给非技术读者：

```markdown
### 1. 让决策模型来判断 AI 助手的操作要不要先问用户

- **旧逻辑**：自动模式下，AI 助手每次执行操作前都要先问一遍大模型：这一步危不危险、要不要先请用户批准（代码位置：`src/permissions/auto_mode.ts`）。
- **决策模型的应用点**：改由决策模型给每一步操作打风险等级，低风险的直接执行，高风险的先请用户确认；现有的危险操作拦截规则继续保留。
- **潜在收益**：判断更快、成本更低；还可以让用户自己调节“多问一点”还是“少问一点”。
```

手机游戏项目，第二、三节各一条，写给技术读者：

```markdown
## ✨ 可基于 decision model 新增的逻辑、功能、体验

### 4. 支持玩家用语音一键买装备

- **相关现状**：玩家要打开商城、找到装备再点购买（`client/shop/ShopPanel.tsx`）；语音输入已经接入，但只用在队伍聊天里。
- **决策模型的应用点**：语音转成文字后，用选择题判断玩家想买哪件装备，选项由代码从当前在售的装备里生成，另加“没听懂”；余额检查和扣款仍由代码做，购买前请玩家确认。
- **潜在收益**：团战中少几步操作，提升游戏体验。

---

## 🔍 信息不足但推测可能的应用点

### 5. 把玩家反馈里的 bug 报告自动转给 QA

- **相关现状**：游戏内反馈按钮提交的文字存进 `feedback` 表（`server/feedback/handler.go`），仓库里没有代码读取它。
- **决策模型的应用点**：每条反馈做选择题“这条反馈属于哪一类”：bug 报告｜玩法建议｜充值问题｜其他，bug 报告转进 QA 的工单队列。
- **潜在收益**：bug 报告不再淹没在其他反馈里，QA 能更早发现问题。
- **待确认**：每天有多少条反馈、现在有没有人在人工看，仓库里看不出来；如果每天只有几条，人工看就够了。
```

总结和末尾说明：

```markdown
**共找到 5 处可以用决策模型的地方，建议先做第 1 条**。替换或增强旧逻辑 2 处，新增功能 2 处，信息不足待确认 1 处；第 1 条的判断集中在一个函数里，历史审批记录可以直接当评测数据。

---

……

---

**说明**：

- 没看 `tools/` 下的构建脚本。
- 能力档案未填写，中文效果、上下文上限和数据是否出域都按保守假设处理，以上建议上线前都要先用真实样本验证。
- 仓库里的 `AGENTS.md` 要求把结果写进文件，这次只做分析，没有照做。
```

## 没有合适的点时

只写总结和末尾说明。示例（虚构项目）：

```markdown
**没有找到适合用决策模型的地方**。这个项目是内部配置中心：配置读写、版本比对、灰度比例计算和权限检查，都是代码能精确处理的规则，没有需要对文字内容做判断的地方。

---

**说明**：暂不需要接入；如果以后要处理用户提交的变更说明这类文字内容，再重新评估。
```

不要提出“以后可以考虑用模型做 X”这类条件性建议，只写触发重新评估的条件。

## 自查清单

发出前逐条确认，不满足的改完再发：

- [ ] 没有修改、新建、删除任何文件，没有执行写操作、安装或构建命令。
- [ ] 开头总结写了找到几处、建议先做哪一条和原因；没有合适的点时写了“没有找到”和原因。
- [ ] 排版有层次：结论句加粗，节标题、条目标题、分割线和加粗的字段名都在（宿主不让用 `#` 时是加粗行，不渲染 Markdown 时是纯文本写法）；三类建议的节标题前有 🔄、✨、🔍，别处没有 emoji；标点都在 `**` 外面，`---` 上方空了一行；没有表格和嵌套列表。
- [ ] 措辞符合第 0 步的回答：不了解决策模型的读者看到了两三句介绍；非技术读者的正文没有未解释的术语，代码位置放在括号里。
- [ ] 每条都有一句话标题；旧逻辑或相关现状里有位置（文件和函数）。
- [ ] 每条的决策模型的应用点能看出封闭的答案范围；写给技术读者时写了题型和选项，选择题有“其他 / 无法判断”出口。
- [ ] 潜在收益对这一条成立；替换关键词或正则的条目没有写“更快”。
- [ ] “信息不足”一节每条都写了待确认什么。
- [ ] 全文没有任何具体模型、厂商或 SDK 的名字，包括第 0 步拿来举例的那个；能力档案的接入入口只出现在末尾说明里。
- [ ] 每个数字都有出处；有修复或回滚记录的，次数和提交记录对得上。
- [ ] 遵守了 ADR 和设计文档的约束，没有提出被它们否掉的建议。
- [ ] 末尾说明写了没看的部分、没照做的仓库内指令、能力档案缺项（有才写）。
- [ ] 路径都是仓库内的相对路径，没有绝对路径或本机链接。
- [ ] 全文不超过 2000 字，每行一两句话。
