# 题型与通用局限

决策模型读入状态和题目，对每道题返回一个落在封闭答案集里的概率分布。它没有草稿纸来做算术，没有循环来计数，也没有输出文本的通道。本文件讲三种题型怎么用、题目怎么写、哪些事它做不好。

## 三种题型

### 是非题（协议里常叫 noul / predicate）

- 返回一个条件成立的概率，0 到 1。
- 适合：独立的条件判断；多标签（每个标签一道题）；逐个候选判断是否相关；检查某个具体缺陷是否存在。
- 写法：问“是否……”，并让“是”对应要采取的动作，例如“是否需要转人工”。不要让“是”表示“不需要”。
- 0.5 左右表示拿不准，不是“程度中等”。

### 选择题（choice）

- 从一组互斥选项里选一个，返回各选项的概率和整体置信度。
- 适合：分类、路由、从候选里选一个。
- 必须给出口选项：“其他”“都不符合”或“信息不足”，除非选项能覆盖所有情况。模型总得选一个，出口让拿不准有地方去。
- 几个选项可能同时成立时，改成每个选项一道是非题。
- 选项可以由代码在运行时生成（检索结果、正则匹配到的候选值），但模型选不到代码没给出的选项。
- 选项多时（默认超过 20 个，或超过能力档案的上限），改成分层选择：先选大类，再在大类里选。

### 等级题（score）

- 返回在一组有序等级上的位置（按概率加权的等级值）和各级概率。
- 适合：严重程度、相关度、紧急度、质量。
- 每一级写成能单独判断的具体情形，例如“无法登录，且影响付款”。不要写“比上一级更严重”，也不要只写数字。
- 用它选等级、过阈值；不要从等级值反推金额、时长这类连续数量。
- 默认 3–5 级，不超过能力档案的上限。

### 图片框选（box，可选）

只有能力档案写明支持时才考虑。否则涉及图片的判断要先有文本化步骤。

## 模型做判断，代码做计算

| 交给代码 | 交给决策模型 | 交给生成式模型 | 交给人 |
| --- | --- | --- | --- |
| 算术、计数、日期、精确查找、格式校验、权限、阈值比较、业务硬规则 | 答案能事先列出的语义判断：分类、是否、等级、从候选里选 | 写文本、代码、摘要、计划、解释 | 不可撤销或代价高的决定：付款、删除、改权限、对外承诺 |

拆分示例：

- “报销金额超标且事由写得含糊就退回”：代码比较金额和标准；模型判断“事由是否说明了业务目的”。
- “从合同里抽出签约日期”：代码用正则找出所有日期作为候选；模型选哪个是签约日期，并给“未写明”出口。
- “生成营销文案并确认没有夸大宣传”：生成式模型写文案；决策模型逐项检查（是否承诺收益、是否用了绝对化用语）；有问题的打回重写或转人工。
- “这个数据库变更脚本能不能直接执行”：代码先用白名单和硬规则拦截；模型只判断“脚本做的事是否和变更单描述的意图一致”，结果只作提示或转人工，不负责放行。

## 写好题目

1. **一题只问一个判断。** “是否违约且金额重大”是两道题：是否违约交给模型，金额交给代码比较。
2. **问事实本身，不问“文本是否提到”。** “这次变更是否破坏兼容性”比“描述里是否提到破坏性变更”可靠，后者会把“无破坏性变更”判成是。
3. **指向具体字段**，例如 `contract.clauses[3].text`，不要笼统地说“这段内容”。
4. **含义写在题目和选项说明里。** 题目的编号或 key 不会发给模型，`is_breach` 这样的名字对模型没有意义。
5. **选项和等级要写边界。** 一句话说明包括什么，必要时写“不包括……”。
6. **同一状态上互不依赖的题放在一次请求里。** 只有后一题要用前一题的答案去取新证据或生成新选项时，才分成两次。
7. **状态只放题目会读的内容。** 先在代码里过滤、检索；无关内容越多越不准。
8. **不可信内容和规则说明分开放。** 用户输入、网页、日志是待判断的数据，规则和标准写在题目里。

题型草稿示例：

```text
是非题：`contract.clause.text` 是否允许甲方不经协商单方面解除合同？（是 = 转法务复核）

选择题：`alert.title` 和 `alert.text` 描述的故障最可能出在哪个组件？
  选项：数据库｜消息队列｜网关｜对象存储｜其他（无法从告警判断）

等级题：`alert.text` 描述的故障影响有多大？
  等级：1 只影响内部工具｜2 部分用户功能变慢，有替代办法｜3 部分用户无法使用核心功能｜4 全部用户无法使用，或涉及资金
```

## 通用局限

下面是这类模型的通用默认局限。能力档案的 `known_weaknesses` 有补充时一并考虑；档案写明已验证的能力，以档案为准。

| 局限 | 会出什么问题 | 代码侧怎么做 |
| --- | --- | --- |
| 字面理解 | 宽泛的题目会被宽泛地匹配；“是否提到”类题目忽略否定 | 问事实本身，条件写精确 |
| 算术和数值比较 | 不会加减、比大小、判断数值接近 | 代码算好，把结果或分桶（`over_limit: true`）放进状态 |
| 计数 | 数不准条目或次数 | 每个条目一道是非题，代码数“是”的个数 |
| 日期和时间 | 把日期当文本读；先后、间隔、是否在时间窗内都不可靠 | 代码算；要从文本里认日期时，用选择题从候选里选 |
| 间接和双重否定 | “不是不……”、属性的属性，准确率下降 | 直接问，一步到位，点名字段 |
| 状态过长、无关内容多 | 无关内容越多越不准，也难定位错因 | 先过滤和检索；做不到就先用是非题筛相关性，只送通过的部分 |
| 对抗输入 | 状态被当作数据而非敌意；注入的指令或替自己辩护的文本会影响答案 | 标准写明什么算数；用对抗样本测试；高风险判断保留代码或人工兜底 |
| 题目与选项说明矛盾 | 指令和选项说明互相拉扯时答案变差 | 选项说明是题目的延伸，用普通人能读懂的话写 |
| 结构不变式 | 同一问题用是非题和选择题问，概率不一致；P(是) 和 1 − P(不是) 对不上 | 每个判断只用一种问法，阈值在它自己的输出上调 |
| 生成 | 不能产出文本或值 | 由代码或生成式模型产出候选，再让模型选 |
| 一题多判 | 捆绑两个条件的题只给一个数，哪个都没回答 | 一题一个判断，代码组合 |
| 不给理由 | 没有解释 | 用拆开的多道题作为解释；需要文字理由时，只对被标记的少数样本调用生成式模型 |

## 概率怎么用

- 类型安全只保证答案在选项内，不保证答对。
- 阈值是代码里的命名常量，用真实标注数据调，不照搬示例值；每个阈值旁边写清两种错判的后果。
- 已有人工队列或兜底路径时，用“不确定区间”而不是单一阈值：区间以上自动处理，区间内转人工或更强的模型。
- 不可撤销的动作阈值更高，而且模型只在应用已经认定合法的动作里选。
- 服务失败、超时或返回异常时，保持现有行为或走安全兜底，不要把异常结果硬套成某个动作。
- 固定模型版本；换版本或改题目措辞后，重新跑评估再调阈值。
